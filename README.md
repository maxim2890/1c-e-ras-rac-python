# Независимые клиенты для администрирования 1С:Предприятия

Два клиента на Python для администрирования 1С:Предприятия. Они используют
стандартную библиотеку Python и выводят результаты в JSON. Оригинальная утилита
`rac` не запускается, библиотеки 1С не загружаются.

| Инструмент | Подключение | Порт по умолчанию | Назначение |
| --- | --- | --- | --- |
| `ras_client.py` | Сервер удалённого администрирования RAS | 1545 | Получение сведений, чтение настроек, мониторинг и администрирование по схеме протокола |
| `rac_client.py` | Агент сервера `ragent`; для подробных настроек — также рабочие процессы | 1540 | Экспериментальный прямой доступ к сведениям о кластерах, настройкам и активным сеансам |

Имя `rac_client.py` обозначает прямой клиент этого проекта. Его интерфейс командной
строки отличается от интерфейса оригинальной утилиты `rac`. Для работы нужен сервер
1С. Для `ras_client.py` дополнительно требуется запущенная служба RAS; прямой клиент
работает без неё.

## Требования и запуск

- Python **3.10 или новее**.
- Сетевой доступ к выбранному сервису и учётные данные, если сервер их требует.
- Для `rac_client.py --details` — доступ к рабочему процессу по адресу, который
  сообщает сервер. Обычно используется порт из настроенного диапазона 1560–1591.

Склонируйте или скачайте репозиторий, перейдите в его каталог и выполните:

```bash
python3 ras_client.py --help
python3 rac_client.py --help
```

Устанавливать пакеты через pip не требуется. Файлы `ras_operations.py`,
`ras_rpc.py` и `protocol_schema.json` должны находиться рядом с `ras_client.py`.
Файл `rac_client.py` работает самостоятельно. Исходный код, параметры командной
строки и имена полей JSON в этом выпуске совпадают с английским выпуском.

## Возможности

### `ras_client.py`

- Автоматическое согласование поддерживаемых версий протокола службы RAS: 10.0–22.0.
- Список кластеров, краткие сведения об информационных базах и реализованные
  параметры информационных баз.
- 42 типизированные операции чтения: серверы, менеджеры кластера, рабочие процессы,
  службы, сеансы, соединения, блокировки, администраторы агента и кластера, правила,
  профили безопасности, счётчики и ограничения.
- 96 типов запросов по схеме протокола, включая изменяющие запросы с локальной
  предварительной проверкой и обязательным флагом `--apply` для отправки.
- Отдельные контексты аутентификации администратора агента, кластера и
  информационной базы.
- Дополнительный вывод полей ответа, содержащих учётные данные.

### `rac_client.py`

- Определение версии и профиля протокола агента сервера, прямое получение списка
  кластеров.
- Автоматический выбор исследованного профиля соединения без защищённого
  начального обмена.
- Аутентификация администратора кластера.
- Получение UUID, имён и описаний информационных баз, а также активных сеансов.
- Чтение реализованных настроек СУБД и информационной базы через рабочий процесс,
  адрес которого сообщает сервер.
- Только чтение: команды постоянного изменения настроек не реализованы.
- Дополнительный вывод чувствительных параметров и исходных полей, назначение
  которых ещё не установлено.

## Примеры для RAS

### Список кластеров и информационных баз

```bash
# Только кластеры
python3 ras_client.py --host 1c.example.net --port 1545 --clusters-only

# Кластеры и краткие сведения об информационных базах
python3 ras_client.py --host 1c.example.net

# Явное указание известной версии протокола службы
python3 ras_client.py --host 1c.example.net --protocol 11.0 --clusters-only
```

### Настройки информационной базы

Замените `CLUSTER_UUID` и `INFOBASE_UUID` идентификаторами из результатов
предыдущих команд:

```bash
python3 ras_client.py --host 1c.example.net \
  --cluster CLUSTER_UUID --infobase INFOBASE_UUID --details \
  --cluster-user administrator --ask-cluster-password
```

Вывод включает тип СУБД, сервер, имя и пользователя базы данных, региональные
настройки, ограничения сеансов, политику регламентных заданий, профили безопасности
и другие реализованные административные параметры. Чтобы включить поля с учётными
данными в том виде, в котором их возвращает сервер:

```bash
python3 ras_client.py --host 1c.example.net \
  --cluster CLUSTER_UUID --infobase INFOBASE_UUID \
  --details --include-sensitive \
  --cluster-user administrator --ask-cluster-password
```

### Версия и мониторинг

```bash
python3 ras_client.py --host 1c.example.net --operation agent.version
python3 ras_client.py --host 1c.example.net --operation server.list --cluster CLUSTER_UUID
python3 ras_client.py --host 1c.example.net --operation process.list --cluster CLUSTER_UUID
python3 ras_client.py --host 1c.example.net --operation session.list --cluster CLUSTER_UUID
python3 ras_client.py --host 1c.example.net --operation connection.list --cluster CLUSTER_UUID
python3 ras_client.py --host 1c.example.net --operation lock.list --cluster CLUSTER_UUID
python3 ras_client.py --host 1c.example.net --operation cluster.admin.list --cluster CLUSTER_UUID
python3 ras_client.py --list-operations
```

Если для чтения данных кластера требуется аутентификация, добавьте
`--cluster-user NAME --ask-cluster-password`. Для операций агента используйте
`--agent-user NAME --ask-agent-password`.

Для операций с несколькими идентификаторами создайте файл `parameters.json`:

```json
{
  "cluster": "CLUSTER_UUID",
  "infobase": "INFOBASE_UUID"
}
```

Получите сеансы выбранной информационной базы:

```bash
python3 ras_client.py --host 1c.example.net \
  --operation session.list-by-infobase --parameters parameters.json
```

Имена параметров операций приведены в выводе `--list-operations`. Не сочетайте
`--operation` с параметрами режима получения списка баз: `--infobase`, `--details`
или `--clusters-only`.

### Запросы по схеме протокола и изменение настроек

Просмотрите точную схему запроса локально:

```bash
python3 ras_client.py --describe-rpc update-infobase-short
```

Например, файл `request.json` для изменения описания информационной базы использует
имена полей схемы. Они отличаются от имён параметров типизированных операций чтения:

```json
{
  "clusterId": "CLUSTER_UUID",
  "info": {
    "infoBaseId": "INFOBASE_UUID",
    "name": "ExampleBase",
    "descr": "Обновлённое описание"
  }
}
```

Проверьте запрос без подключения к серверу:

```bash
python3 ras_client.py --rpc update-infobase-short --protocol 11.0 \
  --request-file request.json --preview
```

После проверки отправьте запрос:

```bash
python3 ras_client.py --host 1c.example.net \
  --rpc update-infobase-short --protocol 11.0 \
  --request-file request.json --apply \
  --cluster-user administrator --ask-cluster-password
```

Для изменяющих запросов необходимы явно указанная версия протокола и флаг
`--apply`. Обязательные поля и ограничения по версиям проверяйте по локальному
выводу схемы.

## Примеры для прямого клиента

### Определение версии и получение списков

```bash
# Начальный обмен, определение профиля и возможностей без чтения административных объектов
python3 rac_client.py --host 1c.example.net --port 1540 --fingerprint

# Список кластеров
python3 rac_client.py --host 1c.example.net

# Краткие сведения об информационных базах
python3 rac_client.py --host 1c.example.net --infobases
```

Режим `--fingerprint` сообщает обнаруженный профиль и версию, полученную от
сервера, если она доступна. При ответе о несовпадении версий клиент может один раз
переподключиться с указанной сервером версией. Версия протокола службы, например
`11.0`, и версия платформы, например `8.3.22.2143`, — разные идентификаторы.

### Настройки и активные сеансы

```bash
python3 rac_client.py --host 1c.example.net --details
python3 rac_client.py --host 1c.example.net --details --include-sensitive
python3 rac_client.py --host 1c.example.net --sessions

# Фильтр по выбранной информационной базе
python3 rac_client.py --host 1c.example.net \
  --cluster CLUSTER_UUID --infobase INFOBASE_UUID --sessions
```

Флаг `--sessions` автоматически включает получение списка информационных баз.
Вывод содержит имена пользователей активных сеансов, идентификаторы приложений,
сеансов, соединений и процессов, время начала и последней активности, адреса
рабочих процессов, региональные настройки, версию клиента и реализованные
параметры жизненного цикла сеанса. Некоторые счётчики доступны только для
исследованного формата служебных сеансов.

Если имя узла рабочего процесса, сообщённое сервером, недоступно из-за контейнера,
NAT или туннеля, можно заменить узел, сохранив выбранный сервером порт:

```bash
python3 rac_client.py --host 127.0.0.1 --port 1540 \
  --details --worker-host 127.0.0.1
```

Порт рабочего процесса также должен быть доступен или проброшен. Чтение подробных
настроек требует соединения с рабочим процессом и не ограничивается портом 1540.

## Аутентификация

RAS-клиент поддерживает ввод пароля без отображения символов:

```bash
python3 ras_client.py --host 1c.example.net \
  --cluster-user administrator --ask-cluster-password
```

Для автоматизации RAS-клиент читает переменные окружения `RAS_AGENT_PASSWORD`,
`RAS_CLUSTER_PASSWORD` и `RAS_INFOBASE_PASSWORD`. Используйте их вместе с
соответствующим параметром `--agent-user`, `--cluster-user` или `--infobase-user`.
Аутентификация администратора информационной базы разрешает выполнение
административных запросов; она не является операцией управления списком пользователей.

Прямой клиент запрашивает пароль при указании имени администратора кластера:

```bash
python3 rac_client.py --host 1c.example.net \
  --infobases --cluster-user administrator
```

Для автоматизации укажите имя переменной окружения, содержащей пароль:

```bash
python3 rac_client.py --host 1c.example.net --details \
  --cluster-user administrator --cluster-password-env ONEC_CLUSTER_PASSWORD
```

Перед запуском задайте эту переменную средствами оболочки или хранилища секретов.
Если учётные данные не указаны, клиент использует пустые значения; решение о
разрешении запроса принимает сервер.

## Чувствительные данные и список пользователей

Флаг `--include-sensitive` включает значения с учётными данными, полученные от
сервера. Он не восстанавливает пароль, скрытый сервером. В проверенной лаборатории
8.3.22 символ `U+FFFD` обозначал скрытое значение и указание сохранить прежний пароль
при обновлении. Клиенты сохраняют и помечают этот маркер, не интерпретируя его как
открытый пароль или шифротекст.

Сейчас оба инструмента получают имена пользователей из активных сеансов. Список
выбора пользователей, который приложение может показывать до аутентификации, не
реализован. Получение всех зарегистрированных пользователей, включая пользователей
без активных сеансов, также не реализовано. Исследование отдельного обмена при
входе в приложение ещё не завершено. Утверждения о невозможности получения такого
списка средствами платформы не делается.

## Совместимость

| Область | Проверки и ограничения |
| --- | --- |
| Протоколы RAS | Реализованы профили 10.0–22.0. Для профилей 12.0–21.0 выполнено меньше проверок на работающих серверах. |
| Проверенные версии платформы для RAS | Отдельные форматы проверены по файлам 8.3.18 и 8.3.22; широкий набор операций мониторинга протокола 22 проверен на работающем сервере 8.3.27.2342. |
| Прямое получение списка кластеров | Проверено на работающих серверах 8.3.22.2143, 8.3.23.2040, 8.3.25.1501, 8.3.27.1559, 8.3.27.1936, 8.3.27.2074 и 8.3.27.2214. |
| Прямое чтение настроек, сеансов и аутентификация | Основные проверки выполнены в лаборатории 8.3.22.2143. Совместимость получения списка кластеров не гарантирует совместимость всех форматов записей. |
| Прямое подключение к 8.3.27.2342 | Защищённый начальный обмен определяется, но не реализован. При наличии RAS используйте RAS-клиент. |
| Учётные данные администратора агента в прямом клиенте | Отдельная аутентификация администратора агента пока не поддерживается. Учётные данные администратора кластера поддерживаются. |

Неизвестные форматы записей и некорректные кадры отклоняются. Совместимость со всеми
версиями 1С не гарантируется. Поле сеанса `client-version` описывает подключившийся
клиент и само по себе не подтверждает версию сервера.

## Вывод и устранение неполадок

При успешном выполнении команда записывает JSON-документ в stdout. При
необходимости сохраните его в файл:

```bash
python3 rac_client.py --host 1c.example.net --infobases > infobases.json
```

Коды завершения: `0` — успех, `1` — ошибка соединения, протокола или сервера,
`2` — неправильные параметры командной строки. Сообщения об ошибках выводятся в
stderr. Отказ в соединении обычно означает, что сервис недоступен или не слушает
нужный порт. При ошибке аутентификации проверьте учётные данные соответствующего
администратора. Ошибка неподдерживаемого профиля означает, что обнаружения версии
недостаточно для установки совместимого соединения. При тайм-ауте рабочего процесса
проверьте сообщённое имя узла, доступность порта и параметр `--worker-host`.

## Тесты

Запустите включённые в репозиторий автономные тесты из его корневого каталога:

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют сохранённые примеры обмена из лаборатории, фрагментированную
передачу, обработку версий, ошибки аутентификации, форматы сеансов, чувствительные
значения, кодирование по схеме и предварительную проверку запросов. Работающий
сервер 1С не требуется. GitHub Actions запускает тот же набор на Python 3.10–3.14.
